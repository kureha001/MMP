## 1. 構成
ファームウェアは役割によりモジュールを分類しています。

| 分類 | 役割 |
|---|---|
|**全体コントローラ**|**ブートシーケンスを行う最上位モジュール**|
||`通信セットアップ`に、**通信機能の初期化**を指示する|
||`機能モジュール`に、**固有の初期化**を指示する|
||**ポーリング**をしながら、`通信アダプタ`に**ルーティング処理**を指示する|
|**2.通信セットアップ**|**ポーリングを開始する前に必要な初期化を行うモジュール**|
||`全体コントローラ`の指示に応じ、処理を開始する|
||`通信アダプタ`に必要な通信資源をセットアップする|
||`各通信アダプタ`に初期化を指示する|
|**通信アダプタ**|**通信経路の固有処理を行い、コマンドを実行させるモジュール**|
||`通信セットアップ`の指示に応じ、接続・認証に関する**情報の格納領域を確保**する|
||`全体コントローラ`の指示に応じ、**ルーティング処理を開始**する|
||ルーティング処理で通信経路の差を吸収(**共通情報を格納**)する|
||`コマンドパーサ`に、**コマンド実行**を指示する|
||コマンド実行結果(共通情報)を**接続元にレスポンス**する|
|**コマンドパーサ**|**機能モジュールにコマンドを処理させるモジュール**|
||`共通情報`を基に、`ベース機能`に、**コマンド実行を指示**する|
||**コマンド実行結果を加工**し、`通信アダプタ`に返す|
|**ベース機能**|**全機能モジュールに共通のインタフェイスを提供するモジュール**|
||`機能モジュール`に、コマンドの`在籍確認`機能を提供する|
||`機能モジュール`に、コマンドの`実行`機能を提供する|
||`コマンドパーサ`の指示に応じ、`在籍確認``実行`機能を実行する|
||`ベース機能`の**実行結果を加工**し、`通信アダプタ`に返す|
|**機能モジュール**|**上位モジュールの指示に応じるモジュール**|
||`全体コントローラ`の指示に応じ、**固有の初期化を実行**する|
||`ベース機能`の`在籍確認`に応じ、**コマンド有無を回答**する|
||`ベース機能`の`実行`に応じ、**コマンドを実行し、結果を共通情報に格納**する|

## 3.通信アダプタ
各通信アダプタにおける実装上の相違について解説します。

### 3-1.内部の相違
見た目でわかる違いをまとめました。

| 略称 |正式名称| 接続方式 | 接続方法 |
| --- | --- | --- | --- |
|Serial|シリアル   |USB-CDC|USBケーブル|
|      |           |UART   |ジャンパケーブル|
|TCP   |TCPブリッジ|WiFi   |無線|
|HTTP  |WebAPI     |WiFi   |無線|

### 3-2.内部の相違
様々な内部的な違いにより、実装する方式が異なります。

| 方式 | Serial | TCP | HTTP |
| ---- | ------ | --- | ---- |
|接続資源|既存の物理ポート<br>(Stream*の参照)|TCP接続<br>(WiFiClientの実体)|既存のHTTPサービス<br>(WebServerの参照)|
|接続情報の単位|ポートごと|TCP接続ごと|HTTPサービス全体で<br>1個を使いまわし|
|接続情報の生成|初期設定時|新規にTCP接続の都度|初期設定時|
|接続情報の寿命|永続|切断すると消失|永続|
|受信の方法|1byteずつ取得<br>(ストリーム)|1byteずつ取得<br>(ストリーム)|一括で取得|
|受信の内容|`パス`/<br>`コマンド名`:`引数1`...:`引数n`!|`パス`/<br>`コマンド名`:`引数1`...:`引数n`!|**認証コード**/`パス`/<br>`コマンド名`:`引数1`...:`引数n`!|
|ユーザ認証の有無|なし|なし|あり|
|レスポンス内容|1ワード(5byte)|1ワード(5byte)|JSON形式<br>(付加情報が多数)|

### 3-3.処理プロセスの相違

| 処理 | Serial | TCP | HTTP | 確定している差異 |
| --- | --- | --- | --- | --- |
| P1 | 本書の確定情報には含まれない | 本書の確定情報には含まれない | 本書の確定情報には含まれない | 差異は未記録 |
| P2 | `P21_RECEIVE` / `P2_MAKE_FRAME` では接続資源を ★★参照★★ として扱う | `P21_RECEIVE` / `P2_MAKE_FRAME` では接続資源を ★★実体★★ として扱う | 本書の確定情報には含まれない | Serial と TCP で参照／実体の差がある |
| P3 | INFO は `cmdPath` のみ | INFO は `cmdPath` のみ | INFO は `authCD` + `cmdPath` | HTTP のみ認証コードを含む |
| P4 | 本書の確定情報には含まれない | 本書の確定情報には含まれない | 本書の確定情報には含まれない | 差異は未記録 |
| P5 | 本書の確定情報には含まれない | 本書の確定情報には含まれない | 本書の確定情報には含まれない | 差異は未記録 |

#### プロセス０：スロットの登録

接続情報を格納する単位をスロットと呼びます。
スロットに登録するタイミングは、アダプタごとに異なります。

| アダプタ | 登録タイミング | 登録指示の関数 |
| --- | --- | --- |
| Serial | システム初期化の直後| `start()`  |
| TCP    | 新たなTCP接続のたび | `handle()` |
| HTTP   | システム初期化の直後| `start()`  |

登録には専用の関数[`SS_ATTACH_SLOT()`]を用います。

---
#### プロセス２：

`P21_RECEIVE` および `P2_MAKE_FRAME` では、Serial と TCP の接続資源の扱い方に差異がある。

| アダプタ | 接続資源の扱い |
| --- | --- |
| Serial | ★★参照★★ |
| TCP | ★★実体★★ |

#### プロセス３：基本情報を取得
受信データは終端文字`!`で区切られており、このひと固まりを**フレーム**と呼びます。
フレーム内の`パス`～`終端文字`までを**コマンドパス**と呼びます。
ユーザ認証のある通信アダプタの場合、フレームの先頭には認証コードが付加されます。

```
(例)
パス1/...パスn/コマンド名:引数1...:引数n!
認証コード/パス1/...パスn/コマンド名:引数1...:引数n!
```

共通関数を利用して内容を求め、コンテクストに反映しています。

| アダプタ | 解説 | 処理後のコンテクスト |
| --- | --- | --- |
| Serial<br>TCP|フレームそのものがコマンドパスになる|`authCD` = 空<br>`cmdPath` = 取得内容 |
| HTTP|認証コード：第１トークン<br>コマンドパス：第２トークン以降のかたまり|`authCD` = 空<br>`cmdPath` = 取得内容 |

#### プロセス６：実行結果をレスポンス
Serial/TCPは、接続先ストリームへ1ワード(5byte)だけを返信します。
HTTPは付加情報とともにJSON形式で返信します。

| アダプタ | 形式 | 戻り値／JSON |
| ------ | -------- |--- |
| Serial | 1ワード  |｛完了／エラーコード／取得値｝のいずれか１つ|
| TCP    | 1ワード  |｛完了／エラーコード／取得値｝のいずれか１つ|
| HTTP   | JSON形式 |到達判定: true(常時)|
|        |          |実行結果: {OK:true｜NG:false}|
|        |          |結果説明: 日本語のコメント|
|        |          |取得数値: 数値型の場合|
|        |          |取得文字: 文字列型の場合|

（アダプタ共通）
| 戻り値 | 内容／コメント |
| ------ | ---- |
|`!!!!!` |OK:戻り値無し             |
|`#CMD!` |NG:コマンド名が不正       |
|`#CHK!` |NG:引数チェックで違反     |
|`#INI!` |NG:データが未初期化       |
|`#DEV!` |NG:使用不可のデバイス     |
|`#FIL!` |NG:ファイル操作が異常終了 |
|`#NOD!` |NG:データ項目名が不正     |
|`#DFL!` |NG:フレーム長オーバー     |
|`#SS0!` |NG:認証管理の開始に失敗   |
|`#SS1!` |NG:ユーザ認証に失敗       |
|`#SS2!` |NG:接続認証に失敗         |
|`-999!`～`9999!` | 取得値（数値）  |
|(上記以外)       | 取得値（文字列）|

（JSON用）
| 戻り値 | 内容／コメント |
| ------ | ---- |
|`#VAL!` |OK:数値   |
|`#STR!` |OK:文字列 |

（認証用）
| 戻り値 | 内容／コメント |
| ------ | ---- |
|`!SS0!` |OK:ユーザ認証に成功     |
|`#SS1!` |NG:認証管理の開始に失敗 |
|`#SS2!` |NG:認証に失敗           |
