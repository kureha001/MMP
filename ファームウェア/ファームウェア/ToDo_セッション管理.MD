# セッション管理方式の変更

## 1. 修正方針・全体サマリー
クライアントの`IPアドレス`が固定されない場合、セッション管理が失敗します。
このため、新たに`認証コード`による特定に変更します。
* クライアントの要求に応じて`認証コードを発行するコマンドを新設`
* クライアントは`URIに認証コードを追加`
* スロットを特定する処理は、`検索キーを認証コードへ変更`

＊これにより現行の後続処理は、これまで通り動作します。
＊物理系ブルで１：１で繋がるシリアル系はマルチスロットの概念が無いので、ロジックの修正はありません。

---

## 2. セッション管理の方式変更
* **セッションキーの変更**
スロットを特定する検索キーを`IPアドレス`から`認証コード`へ変更します。
  * 認証コード発行関数を追加する(戻り値：成功=スロットTBLの配列添え字／失敗=-1)
  * URIの第一トークンから認証コード発行要求コマンド("_START_")を検出し、認証コードを発行する
  * 発行処理後はレスポンス処理に進む
  * MMPコマンド実行前に認証コード(URIの第１トークン)を取得する
  * スロットTBLの配列添え字を取得する処理を認証コードで行うよう変更する
  * 不要になった古いコードは削除する

* **認証コード発行関数[getSlot_index()]の仕様**
  * 認証コードは英数字（`0-9`, `A-Z`, `a-z` ）を用いた **ランダムな5文字** で生成する
  * 認証コードはスロットTBL内でユニークであること
  * 通常は空きスロットに割り当てる
  * **スロットが満杯の場合**、最終アクセスから **30分** 経過したスロットを再利用する
  * それでもスロットが用意できない場合は戻り値に「失敗」を返す

* **スロットTBLの仕様**
  * `cli.h`の構造体定義(現行：`typeIP`)、これを用いる実体(広域変数名)を以下のように変更する
  * 実体(現行：`g_IP_TCP`,`g_IP_HTTP`)はプロジェクト内で正しい名称へ全置換する
  * 広域定数(現行：`MAX_IP`)はプロジェクト内で`MAX_SLOT`へ全置換する
  * 他(シリアル系・機能モジュール系など)に影響があれば適宜修正する
```
//─────────────────
// スロットTBL管理
//─────────────────
struct typeSlot {
  String   authCode        = ""       ; // 認証コード
  bool     inUse           = false    ; // 有効性判定
  unsigned long lastAccess = 0        ; // 最終アクセス日時
}; /* typeSlot */
static typeSlot g_Slot_TCP[MAX_SLOT]  ; // TCPブリッジ用
static typeSlot g_Slot_HTTP[MAX_SLOT] ; // Web-API用
```

## 3. エラー処理について
認証コード発行関数が「失敗」となった場合、例外処理を行います。
既存のソースリスト(cliHttp.h：`if (ipKey < 0) {`の部分)を参考にしてください。
また、以下の新設したエラーIDを使います。

* **`#FUL!` (Full)**
  * 新規発行時にスロットが満杯になった場合のエラー。
  新設する認証コード発行処理のコール直後に設ける。

## 4. Web API接続時のJSONレスポンスの修正
前章のエラーID利用に伴い、HTTP側のエラーメッセージマッピングを修正します。

```cpp
  static const char* map_error(const String& resp){
    if (resp == "#CMD!") return "Error:コマンド名が不正"      ;
    if (resp == "#CHK!") return "Error:引数チェックで違反"    ;
    if (resp == "#INI!") return "Error:データが未初期化"      ;
    if (resp == "#DEV!") return "Error:使用不可のデバイス"    ;
    if (resp == "#FIL!") return "Error:ファイル操作が異常終了";
    if (resp == "#NOD!") return "Error:データ項目名が不正"    ;
    if (resp == "#SID!") return "Error:未定義の経路ID"        ;
    if (resp == "#FUL!") return "Error:認証スロットが満杯"    ; // 追加
    if (resp == "#MEM!") return "Error:認証コードが不正"      ; // 変更
    return "Error:その他のエラー";
  } /* map_error() */
```
  ※ここで定義したメッセージは、JSONレスポンスに反映されます
