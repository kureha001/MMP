# 1. 通信アダプタのクラス設計

通信アダプタは、３つの型(抽象基底クラス)を利用して実体化します。

#### 【基本型】
HTTP(GET)のように、**一度の通信でリクエスト＆レスポンスで完結**する通信は、この型を利用します。
このほかの用途として、後述する2つの型(`接続スロット型`,`非同期キュー型`)の基底クラスとして機能します。

#### 【接続スロット型】
UART/TCPのように、**逐次処理 かつ 複数の常時接続**をもつ通信は、この型を利用します。
 - 接続毎に**スロット**と呼ばれるデータレコードを用意します。
 - 接続オブジェクト(実体または参照)を`接続識別子`としてスロットに格納します。
 - 処理結果の送信先は、『スロットの`接続識別子`』を用いて特定します。
 - ポーリングで**受信・応答を同時に行う**ので、`非同期キュー型`のようなオーバーヘッドがありません。<br>ただし、通信負荷が高くなると、この利点が薄れます。

#### 【非同期キュー型】
**コールバックで受信**する通信は、この型を利用します。
 - **非同期で受信しながらキュー登録**します。
 - キュー登録の際、接続元を特定する情報(`接続識別子`)を格納します。
 - 蓄積したキューは、逐次処理でポーリング応答(**キュー取得＋応答**)します。
 - 処理結果の送信先は、『キューの`接続識別子`』を用いて特定します。

#### 【非同期キュー型＋接続スロット型】
逐次処理の`接続スロット型`を`非同期キュー型`として利用する場合は、この型を利用します。
**ポーリング処理のコーディングが不要**になり、保守性が向上します。
高負荷時は、**処理全体が平滑化**されるメリットもあります。
 - データ受信部を並列処理化します。
 - **並列処理で受信しながらキュー登録**します。
 - キュー登録の際、『接続スロットの`接続識別子`』を格納します。
 - 以降は`非同期キュー型`と同じです。

# ２. 抽象基底クラス群

`純粋仮想関数` `仮想関数` を必要に応じて、`継承`または`実装(オーバーライド)`して利用します。
`非同期キュー型`,`接続スロット型`は`基本型`を基底クラスとしています。
`非同期キュー型`,`接続スロット型`には、固有の処理方式に必要な`メンバ関数`を多数用意しています。
`接続スロット型`には純粋仮想関数(`ON_RECIVE()`)が用意されているので、アダプタ側でデータ受信に関する実装が必須になります。

|関数種別|関数名|モード別分割|基本型／目的|非同期キュー型|接続スロット型|
| :---| :--- | :--- | :--- | :--- | :--- |
|**純粋仮想関数**|**`handle()`** |－| ハンドルの全体フロー | **【基本型を実装】**<br>非同期キュー処理方式 |<br>アダプタで実装する(**必須**)|
|仮想関数| **`CONSTRACT()`** |－|コンストラクタの固有差分<BR>※**ダミー処理**を実装済|||
|仮想関数| **`SEND_REQUEST()`** |－|スレーブが自身にリクエストを送信する<BR>※**ダミー処理**を実装済|||
|仮想関数| **`SEND_RESULT()`** |－|接続元に処理結果を送信する<BR>※**ダミー処理**を実装済|||
|仮想関数| **`SETUP_OPTION()`** |－|ハンドル初期化の個別差分<BR>※**ダミー処理**を実装済|||
|仮想関数| **`WORKFLOW()`** |ブリッジ用|マスタとスレーブの連携フローを制御する<br>※**スレーブ用**の処理を実装済|||
|仮想関数|**`RUN_PROCESS()`**|ブリッジ用|`ブリッジモード`のキュー応答<br>※**スレーブ用**の処理を実装済|||
|||メイン用|`メインモード`のキュー応答<br>※実装済 |||
|||サブ用|`サブモード`のキュー応答<br>※実装済 |||
|**純粋仮想関数**|**`ON_RECIVE()`** |－|➡|➡|**このクラス固有の関数**<BR>データ受信の処理を実装する(**必須**)|

## 3-1. BLEアダプタ

#### §特徴
非同期キュー型の通信アダプタです。
通信サービスはBLEひとつで、全モードを実現します。
通信内容に応じて、BLEサービスがもつ個別のI/Fを利用します。
受信はコールバック関数を用いますが、一部特定のクラスをオーバーライドする点が特徴的です。

|動作モード|目的|データ種別|通信資源|解説|
|----------|----|----------|--------|----|
|メイン／サブ|受信|リクエスト| BLE(コールバック関数) |規定のクラスをオーバーライド|
|            |送信|処理結果  | BLE(TX)               |通信端子にTXを利用|
|ブリッジ    |送信|リクエスト| BLE(RX)               |通信端子にRXを利用|
|            |受信|処理結果  | BLE(コールバック関数) |任意のコールバック関数|

#### §ファイル構成
`全モードの基底ファイル`,`メイン・サブの差分`,`ブリッジモードの差分` の3ファイルで構成します。

| ファイル | 目的 | 内容 |
| -------- | ---- | ---- |
| BLE.cpp         | 全モードの基底           | オーバーライドは一切なし |
| BLE_MainSub.cpp | メイン／サブモードの差分 | ・`CONSTRACT()`<BR>・`SEND_RESULT()`<BR>・独自のデータ受信 |
| BLE_Bridge.cpp  | ブリッジモードの差分     | ・`CONSTRACT()`<BR>・`SEND_REQUEST()`<BR>・独自のリクエスト送信 |

#### §抽象基底クラスとの関連
通信内容に応じて個別のI/Fを利用するので、コンストラクタ差分(`CONSTRACT()`)はモード別に実装します。
ハンドルの初期処理差分はありません。
そのほかは、オーソドックスな内容です。

| 仮想関数 | メイン/サブモード | ブリッジモード | 解説 |
| :--- | :---: | :---: | :--- |
| **`CONSTRACT()`** |**【実装】**|**【実装】**| 各モードのファイルで独自にオーバーライド |
| **`SEND_REQUEST()`** |(未使用)|**【実装】**| ・メイン/サブには**便宜上存在する**が使用しない<BR>・ブリッジはオーバーライド |
| **`SEND_RESULT()`** |**【実装】**|(未使用)| ・メイン/サブはオーバーライド<BR>・ブリッジには**便宜上存在する**が使用しない |
| **`SETUP_OPTION()`** |(参照)|(参照)| 基底クラスの**仮実装**を利用 |
| **`WORKFLOW()`** |≪なし≫|(参照)| ブリッジでは基底クラスの実装(**スレーブ用**)を利用 |
| **`RUN_PROCESS()`** |(参照)|(参照)| 基底クラスの実装(**モード別**)を利用<BR>(ブリッジ用は**スレーブ用**で実装済) |
| **`ON_RECIVE()`** |≪なし≫|≪なし≫| **スロット型の機能**であり存在しない |
| **`handle()`** |(参照)|(参照)| **非同期キュー型で実装した共通処理**を利用 |
